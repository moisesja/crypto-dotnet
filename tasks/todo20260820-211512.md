## Review

### Implementation

- `FromKeyPair` now uses the same private validation helpers as `FromRawKey`: defined key type,
  canonical public-key length, then exact private-key scalar/seed length inside the copy-free
  `WithPrivateKey` borrow. This keeps validation order and exception parameter names aligned
  across both factories and prevents the sibling paths from drifting again.
- Regression coverage spans null and empty inputs, undefined enums, both shorter and longer
  public/private lengths for all eight key types, the realistic 64-byte libsodium Ed25519 secret,
  accepted expected lengths, and source ownership.
- FR-7b rule 13 and XML documentation now state the entry-point guarantee, including the
  intentional component-level `ParamName` values returned by `FromKeyPair`. Repository version
  and changelog/compare links are prepared for 1.7.1. No public API changed, and
  `PublicAPI.Unshipped.txt` has no entry to promote.

### Regression proof

- With only the new production validation removed, the `FromKeyPair_Rejects*` selection produced
  36 intended failures (`Expected ArgumentException ... but no exception was thrown`); the sole
  passing case was the pre-existing null guard. After restoring the fix, the complete
  `TransferableKeyMaterialTests` suite passed 63/63.

### Input-validation sweep

- Family (a): null pair and empty public/private material produce exact parameter-named
  `ArgumentNullException`/`ArgumentException`.
- Family (b): every key type was probed with wrong public/private lengths; the adversarial harness
  additionally covered 0, 1, expected±1, 2× expected, and 1 MB buffers.
- Family (c): correctly sized but semantically invalid/mismatched material remains a deliberate
  factory success because this owner invokes no crypto backend; the receiving store independently
  derives identity, rejects the mismatch as `ArgumentException("request")`, spends the transfer,
  and commits nothing. Existing store coverage plus the executable adversarial probe confirms the
  FR-7b rule 13 split.
- `InputValidationFuzzTests` plus focused transfer tests passed 366/366.
