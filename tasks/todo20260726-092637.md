# Fix PR #22 Return-Path Boundary Gaps

## Scope

Address all three findings from the 2026-07-26 follow-up review without changing the public API:

1. reject non-secp256k1 `KeyStoreSigner.SignDigestAsync` calls before touching the store;
2. reject high-S backend signatures even when an adjusted recovery id recovers the advertised key;
3. clone backend-owned signature bytes before validation and return the verified clone.

## Review

Implemented the three follow-up review fixes without changing the public API:

- non-secp256k1 `KeyStoreSigner` instances reject before touching the store;
- provider output must be structurally valid, low-S, and recover to the private advertised-key
  snapshot;
- provider signature bytes are cloned before validation and only the verified clone is returned.

The independent defensive pass wrote and ran 18 additional tests. All intended defenses held, and
it found two additional mutable-memory gaps:

1. constructor/exposed public-key memory could change the identity used by the recovery guard;
2. an arbitrary store could mutate caller-backed digest memory, sign the changed digest, and have
   post-call verification observe the same changed bytes.

Both were fixed and permanently regression-tested. `KeyStoreSigner` now keeps a private public-key
snapshot, returns defensive public-key copies, keeps a private verification-digest snapshot, and
hands the provider a separate digest copy.
